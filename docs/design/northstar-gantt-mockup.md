# Разбор макета «Northstar»

Структурный разбор `northstar-gantt-mockup.html` — второго макета экрана
проекта с диаграммой Ганта. Первый разобран в `planora-mockup-analysis.md`;
тот в репозитории не сохранён и существует только как текст, поэтому здесь
сам файл лежит рядом с разбором.

Макет — один самодостаточный HTML: ~250 строк CSS, ~145 строк разметки,
~85 строк JS, ни одной внешней зависимости. Это кликабельный прототип, а не
заготовка кода: почти вся геометрия — литералы в атрибуте `style`.

Состояние на экране: четверг 13 августа 2026, масштаб «Day», выбрана задача
«Create wireframes», открыта её панель, снизу висит тост «Task moved to Aug 13».

## 1. Каркас

```
body (overflow:hidden)
└ .app                      grid: 228px | 1fr
  ├ aside.sidebar           тёмная (#182032), единственная тёмная зона
  └ main.main               flex-column
    ├ .topbar               52px — хлебные крошки, поиск, уведомления
    ├ header.project-head   заголовок + действия + 5 метрик
    └ section.gantt-shell   flex:1, position:relative — система координат
      ├ .gantt-toolbar      sticky, z-25
      ├ #ganttScroll        overflow:auto — единственный скроллер ленты
      │ └ .gantt-stage      min-width: 410px + 1092px
      │   ├ .gantt-head     68px, sticky top   ┐ grid: 410px | 1fr
      │   └ .gantt-body     min-height 620px   ┘ grid: 410px | 1fr
      ├ .legend             absolute, снизу слева
      ├ #drawer             absolute, справа, transform-слайд
      ├ #snackbar           absolute, снизу по центру
      └ #tooltip            position:fixed — единственный fixed-элемент
```

Ключевой приём: **двухосевая заморозка на одном скроллере**. Шапка ленты
(`.gantt-head`) липнет по `top`, колонка задач (`.task-head`, `.task-list`) —
по `left`; их пересечение (`.task-head`) заморожено по обеим осям и получает
z-index выше обоих. Второго скроллера и синхронизации через JS нет — этим
макет выгодно отличается от типовых реализаций Ганта.

Лестница слоёв выстроена аккуратно и без конфликтов:

| z | Слой |
|---|---|
| 200 | tooltip |
| 100 | snackbar |
| 80 | popover |
| 55 | drawer |
| 40 | sidebar |
| 25 / 24 | toolbar / legend, `.task-head` |
| 20 | `.gantt-head` |
| 15 | `.task-list` |
| 6–10 | слой связей, дедлайны, коннекторы |
| 4–5 | линия «сегодня», бары |

Панель задачи — **оверлей поверх ленты** (`position:absolute` внутри
`.gantt-shell`), а не третья колонка. Это осознанное расхождение с первым
макетом, где инспектор ужимал канву. Следствие: при открытой панели правый
край ленты закрыт, горизонтальный скролл её не сдвигает.

## 2. Дизайн-система

24 переменные в `:root`: 15 цветовых, 5 геометрических (`--row: 48px`,
`--group-row: 44px`, `--day: 52px`, `--task-pane: 410px`, `--drawer: 404px`),
тень. `--cyan` объявлен и нигде не использован.

Акцент — индиго `#5367e8` (в первом макете был `#2563EB`), семантика цвета
та же и разведена так же строго: зелёный `#29a36a` — сделано, янтарный
`#e69a2d` — черновик и просрочка, розово-красный `#d94c71` — нарушение срока
и блокировка, серый `#8d97ab` — сводные линии категорий. У каждого
семантического цвета есть `-soft` версия для фона чипов.

Шрифт: `font: 14px/1.45 Inter, …` — Inter объявлен, но нигде не подключён
(ни `@font-face`, ни `<link>`), то есть фактически виден системный. Ровно та
же ошибка, что зафиксирована пунктом 12 разбора первого макета.

**Статус задачи рисуется четырьмя параллельными способами** — и это главная
структурная особенность дизайн-системы макета:

| | planned | progress | done | blocked | overdue |
|---|---|---|---|---|---|
| `.state-icon` (иконка в списке) | базовый | ✓ | ✓ | ✓ | — |
| `.pill` (чип в списке) | базовый | ✓ | ✓ | ✓ | ✓ |
| `.bar` (полоска) | ✓ | ✓ | ✓ | ✓ | ✓ |
| `.legend-swatch` | ✓ | базовый | ✓ | ✓ (общий с blocked) | — |

Слой иконок неполон: у `overdue` иконки нет, поэтому просроченная «API
integration» показана иконкой «в работе» и чипом «Overdue» одновременно.
Легенда склеивает blocked и overdue в одну плашку. Пять состояний, четыре
представления, три разных набора — при переносе в код это надо свести к
одному источнику.

Формы: радиусы 5–10px, чипы — полные пилюли, тени мягкие и заметные
(`--shadow: 0 12px 36px rgba(16,24,40,.13)`) — в отличие от первого макета,
где глубина почти не использовалась.

## 3. Геометрия ленты — и её главный дефект

Единица — день = `--day: 52px`, 21 день (10–30 августа), итого **1092px**.
Это число зашито в пяти местах: `.gantt-stage`, `.timeline-head`,
`.timeline-body`, `width` и `viewBox` слоя связей. Высота — 620px, зашита
в `.gantt-body` и в том же `viewBox`.

Вертикаль: 3 строки категорий по 44px + 8 задач по 48px = **516px**
фактического содержимого при заявленных 620px.

### 3.1. Два источника правды по горизонтали

Часть разметки считает координаты через `calc()` от `--day`, часть — нет:

| Элемент | Как задан | Переживёт смену масштаба |
|---|---|---|
| Колонки шапки `.days` | `repeat(21, var(--day))` | да |
| Штриховка сетки | `repeating-linear-gradient` от `--day` | да |
| Выходные `.weekends` | `calc(5 * var(--day))` и далее | да |
| Линия «сегодня» | `calc(3 * var(--day) + var(--day)/2)` | да |
| **Бары, дедлайн, метка слипа** | **литералы `left`/`width` в px** | **нет** |
| **Слой связей (SVG)** | **абсолютные координаты пути** | **нет** |
| **`min-width` ленты** | **1092px** | **нет** |

Кнопки масштаба меняют `--day` (52 → 30 → 18px). После первого же нажатия
сетка, выходные и «сегодня» сжимаются, а бары, стрелки и ширина полотна
остаются на месте: шапка занимает треть ширины, бары висят над пустотой.
Это не косметика — это признак того, что **макет не задаёт правила расчёта,
только одну застывшую картинку**. Для реализации отсюда следует единственный
вывод: координаты обязаны считаться из шкалы, как это уже сделано
в `gantt/timescale.ts` и `gantt/Arrows.tsx`.

### 3.2. Стрелки нарисованы по другой модели строк

Пути в SVG проложены по сетке строк, которая расходится с DOM: слой связей
считает строку категории «Design» высотой 24px вместо 44, а строку
«Development» — нулевой.

| Задача | Центр бара в DOM | Y в SVG | Расхождение |
|---|---|---|---|
| Define project scope | 116 | 116 | 0 |
| Create wireframes | 208 | 188 | −20 |
| Design system | 256 | 236 | −20 |
| Interactive prototype | 304 | 284 | −20 |
| API integration | 444 | 380 | −64 |
| QA & launch | 492 | 428 | −64 |

То есть в отрисованном виде стрелки нижней половины диаграммы промахиваются
мимо баров на 20 и 64 пикселя. У «Frontend implementation» связей нет вовсе,
хотя по смыслу она — преемник прототипа.

### 3.3. Пиксели баров не выведены из дат

Даты живут только в объекте `tips` для тултипов, позиции — в атрибутах
`style`. Сверка расходится до полутора суток:

| Задача | Тултип | Фактически занимает |
|---|---|---|
| User research | 10 → 12 авг | 10.5 → 13.0 |
| Define project scope | 12 → 14 авг | 12.2 → 14.9 |
| Create wireframes | 13 → 18 авг | 13.5 → 18.3 |
| API integration | 23 → 28 авг | **22.5** → 28.0 |
| QA & launch | 28 → 30 авг | 27.8 → 30.5 |

Соглашение о границах тоже плавает: начало у одних баров — середина дня,
конец у одних — середина, у других — начало последнего дня.

### 3.4. Строка «＋ Task» ломает выравнивание колонок

`#inlineAdd` (48px) вставлен **между** «Interactive prototype» и категорией
«Development» внутри `.task-list`, и парной строки в `.timeline-body` у него
нет. Пока он скрыт — всё сходится; после нажатия «＋ Task» весь низ таблицы
уезжает на 48px относительно своих баров. `.add-category` (46px) страдает
тем же, но стоит последним и потому безвреден.

## 4. Продуктовая модель, заложенная в макет

Иерархия ровно двухуровневая: проект → категория → задача. Вложенность
глубже не предусмотрена — каретка сворачивает один уровень, отступ задан
одним литералом `padding-left: 28px`.

**Задача:** название, один исполнитель (аватар + имя), статус, даты начала и
конца, процент готовности, описание, зависимости в обе стороны
(«Depends on» / «Blocks»), ключ вида `DES-104` (нумерация внутри категории).

**Категория** агрегирует: исполнителя, статус, счётчик «2 / 2 done», сводную
полосу со стрелочными засечками.

**Проект:** статус Draft → Approved (то есть заложен цикл утверждения плана),
пять метрик, «Edited 4 min ago», шаринг, экспорт в PDF, архив, удаление.

Отдельно стоит **дедлайн как сущность, независимая от даты конца**:
у «API integration» есть вертикальный ограничитель на 26 августа, бар кончается
28-го, между ними — метка «+2d» и тултип «Original deadline / Current finish».
Это baseline-модель: план фиксируется при утверждении, а дальше сравнивается
с фактом.

Связи — только finish-to-start (все пути идут от правого края к левому),
с состоянием «нарушение» (красный пунктир + кружок «!»). Правило, по которому
связь становится нарушенной, из макета не выводится: помеченная связь
prototype → api идёт с 628px на 650px, то есть без пересечения. Метка
поставлена по смыслу («предшественник заблокирован»), а не по геометрии.

### 4.1. Противоречия в цифрах

- Категория «Design» подписана **«1 / 3 done»**, но среди её задач
  (wireframes — in progress, system — planned, prototype — blocked)
  завершённых нет. Должно быть 0 / 3.
- Метрики в шапке не сходятся: 3 in progress + 2 done + 1 blocked +
  1 overdue = 7 при заявленных 8 задачах, а ещё две задачи в статусе
  Planned нигде не учтены. Сходится это только если считать «Overdue»
  **флагом поверх статуса**, а не статусом: тогда «API integration» попадает
  и в «in progress», и в «overdue». Но чип и легенда рисуют overdue именно
  как статус.
- У категории «Development» статус **«At risk»** — шестое значение, которого
  нет ни в легенде, ни в списке `<select>` в панели (там всего четыре:
  In progress / Planned / Done / Blocked, без Overdue и At risk).

Это не придирки к макету, а нерешённый продуктовый вопрос, который придётся
закрыть до реализации: **статус — одно поле из перечисления или поле плюс
вычисляемые флаги (просрочен / под угрозой)?** Макет молча предполагает
второе, но рисует первое.

## 5. Слой поведения

85 строк без фреймворка и без модели состояния — все изменения вносятся
прямой правкой DOM.

| Механика | Что делает | Чего не делает |
|---|---|---|
| Генерация дней | Единственный настоящий расчёт: 21 ячейка, выходные по `i % 7`, «сегодня» по числу | — |
| `popover()` | Клик-переключение, закрытие по документу | без клавиатуры и `aria-expanded` |
| `selectTask(id)` | Связывает панели по `data-id`: подсветка строки слева, строки и бара справа, открытие панели | переносит в панель **только название**; статус, исполнитель, даты, 62%, описание и связи остаются от wireframes |
| Подсветка при наведении | `mouseenter` на любом `[data-id]` подсвечивает обе половины строки | — |
| Сворачивание категории | `hidden` на `[data-group]` в обеих панелях | не обновляет счётчики; слой связей остаётся в прежней геометрии и указывает в пустоту |
| Inline-добавление | Показ строки, Esc/Enter, тост | строку не создаёт |
| Тост | Общий `showSnack()`, таймер 5.2с | «Undo» показывает другой тост |
| Approve | Меняет бейдж и блокирует кнопку | — |
| «Today» | `scrollTo({left: 125})` | магическое число, верное только при `--day: 52px` |
| Масштаб | Меняет `--day` и подпись периода | не пересчитывает ничего из п. 3.1 |
| Тултипы | Словарь из 9 записей, следование за курсором с переворотом у краёв экрана | — |
| Перетаскивание бара | `pointerdown/move/up` с захватом указателя, правка `style.left`, тост по факту сдвига | без привязки к сетке дней, без пересчёта дат, без перерисовки связей, без ограничения справа |

Отдельно: `.handle` (ручки растягивания) и `.connector-dot` (точка протяжки
связи) отрисованы и появляются по наведению, но обработчик `pointerdown`
специально выходит, если нажатие пришлось на них. То есть **растягивание
сроков и создание связей мышью в макете заявлены визуально, но не работают** —
их поведение придётся проектировать с нуля.

Прогресс зашит дважды и одинаково: `.bar.progress::before { width: 62% }` и
`.progress-track span { width: 62% }`. Поэтому у «Frontend · 35%» и
«API integration · 60%» заливка всё равно 62% — подпись и картинка
противоречат друг другу.

## 6. Адаптивность

Три состояния, и все три получены переопределением переменных в `:root`
внутри медиазапросов — приём аккуратный, за счёт него всё сжатие умещается
в несколько правил.

**≤1180px:** сайдбар 228 → 70px (подписи, бейджи и переключатель воркспейса
скрываются, остаются иконки); `--task-pane` 410 → 340; `--drawer` 404 → 390;
**колонка «Status» исчезает** — и в шапке, и в строках сетка
переопределяется на две колонки, а третий потомок гасится.

**≤850px:** сайдбар схлопывается в ноль; шапка проекта складывается
в столбец, действия уезжают под заголовок; метрики и тулбар получают
собственный горизонтальный скролл; `--task-pane` → 300px; панель задачи →
`min(92vw, 404px)`; легенда скрывается.

Полотно ленты при этом остаётся 1092px, так что на телефоне горизонтальный
скролл огромен — судя по всему, намеренно.

## 7. Доступность

Что есть: `aria-label` у ориентиров и всех иконочных кнопок, `role`-разметка
через семантические теги (`aside`, `main`, `header`, `nav`), корректная
обработка `[hidden]`, видимый `:focus-visible` с толстым контуром.

Чего нет: строки — это `div` с обработчиком клика, без `role`, `tabindex`
и клавиатуры; у каретки нет `aria-expanded`; панель задачи не диалог и не
удерживает фокус; тултип не связан с элементом через `aria-describedby`;
переключатель масштаба не `radiogroup`; нет `prefers-reduced-motion`.

Отдельная странность: `lang="ru"`, весь видимый текст — английский,
а `aria-label` — русские. Экранный диктор будет читать английские подписи
с русской озвучкой.

## 8. Что из этого следует для реализации

Макет полезен как **описание композиции и дизайн-системы** и вреден как
источник геометрии. Разделение проходит ровно по границе «свёрстано
переменными / вбито литералами».

Брать как есть:

1. Схему двухосевой заморозки на одном скроллере — она рабочая и лучше того,
   что обычно пишут вручную.
2. Лестницу z-index — конфликтов в ней нет.
3. Приём с переопределением `:root` в медиазапросах, включая исчезновение
   колонки Status на средних экранах.
4. Панель задачи как оверлей — но это сознательная смена решения
   относительно первого макета, её стоит подтвердить явно.
5. Дедлайн как сущность отдельно от даты конца (метка «+2d») — единственная
   по-настоящему новая продуктовая идея в этом макете.

Не брать:

6. Любые пиксельные координаты. В коде уже есть правильный подход:
   `gantt/Arrows.tsx` явно считает координаты из шкалы и `ROW_HEIGHT`,
   а не измеряет DOM, — комментарий там описывает ровно тот дефект,
   которым болеет макет (п. 3.2).
7. Литерал 62% для прогресса.

Решить до кода:

8. **Статус: перечисление или поле + флаги?** (п. 4.1) От этого зависят
   и чип, и иконка, и легенда, и метрики, и `<select>` в панели.
9. Поведение ручек растягивания и протяжки связей — в макете их нет (п. 5).
10. Правило, по которому связь считается нарушенной (п. 4).
11. Привязка перетаскивания к сетке дней и пересчёт дат.

Мелочи, которые дешевле поправить сразу: подключить Inter, убрать `--cyan`,
исправить счётчик «1 / 3 done», выровнять `lang` и язык `aria-label`,
дать `#inlineAdd` парную строку в ленте (п. 3.4).
