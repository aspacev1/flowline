# Разбор макета Planora

Глубокий анализ макета «Planora» — экрана проекта «Website Redesign» с диаграммой
Ганта, — по которому уже шли два прохода редизайна (`6c8ede1`, `744a1e8`).
Сам файл макета в репозитории не хранится; единственное его описание в коде —
шапка `frontend/src/broadsheet-theme.css`. Этот документ фиксирует макет как
текст: устройство экрана, дизайн-систему, продуктовые механики, которые макет
постулирует неявно, его внутренние противоречия — и, главное, расхождения с
текущей реализацией, чтобы третий проход не искал их заново.

Дата в макете — четверг, 13 августа 2026, вид «Day», выбрана задача
«API integration», открыта её панель.

---

## 1. Композиция экрана

Три вертикальные зоны, светлая тема:

```
┌──────────┬────────────────────────────────────────────┬──────────────┐
│ Сайдбар  │ Шапка проекта (2 яруса)                    │ Инспектор    │
│ ~230px   ├────────────────────────────────────────────┤ задачи       │
│          │ Тулбар таймлайна                           │ ~360px       │
│          ├──────────────┬─────────────────────────────┤              │
│          │ Таблица задач│ Канва Ганта                 │              │
│          │ (3 колонки)  │ (день = колонка)            │              │
└──────────┴──────────────┴─────────────────────────────┴──────────────┘
                       ▲ тост «Task moved to Aug 19 · Undo» поверх, снизу по центру
```

Инспектор — не оверлей, а третья колонка: канва ужимается, шапка проекта
частично уходит под панель (кнопки «Share» и «⋯» стоят левее панели).

## 2. Дизайн-система

**Типографика.** Гротеск класса Inter. Заголовок проекта ~28–32px/700;
основной текст 14–15px; метаданные и подписи 13px приглушённым серым.
Числа дат в линейке — крупные, день недели под ними капителью 10–11px.

**Цвет.** Белый фон, серо-голубые границы (~`#E5E9F0`), почти чёрный текст
(~`#111827`), приглушённый серый (~`#6B7280`). Один насыщенный акцент — синий
~`#2563EB`…`#2E5BFF`: primary-кнопки, активные пункты навигации, бары «в
работе», линия «сегодня», прогресс в панели, ссылка «Undo». Семантика:

| Роль | Цвет | Где |
|---|---|---|
| Синий | ~`#2563EB` | акцент, In progress, today, прогресс |
| Зелёный | ~`#16A34A` на `#EAFBF1` | Done: чип и бар с галочкой |
| Оранжево-янтарный | ~`#D97706`/`#F59E0B` | Blocked, бейдж Draft |
| Серый | контурный | Planned: чип и «пустой» бар |
| Фиолетово-индиговый | ~`#6D5AE0` | сводные линии категорий |
| Красный | ~`#E11D48` | просрочка: метка «+4d» и вертикальный ограничитель |

Красный и оранжевый разведены: оранжевый — состояние (заблокировано, черновик),
красный — нарушение срока. Фиолетовый существует только чтобы сводная линия
категории не читалась как ещё один таск-бар.

**Формы.** Радиусы 6–10px; чипы статусов — полностью скруглённые пилюли с
тонирован­ным фоном и рамкой в тон текста. Тени почти отсутствуют — глубина
задаётся границами; заметная тень только у тоста и, вероятно, у дропдаунов.
Аватары — круглые фотографии ~28px.

## 3. Сайдбар

Логотип-плитка «P» с градиентом + словомарка «Planora». Навигация из пяти
пунктов с иконками: Home, My tasks, **Projects** (активный — синий текст на
светло-синей пилюле `#EEF4FF`), Team, Reports. Внизу — аватар текущего
пользователя, имя «Taylor Smith» и шеврон меню аккаунта. Никакого верхнего
хедера в приложении нет — весь глобальный хром живёт в рейле.

## 4. Шапка проекта (два яруса)

**Ярус 1.** Слева: заголовок «Website Redesign»; под ним строка метаданных
«Aug 13 – Aug 26 · 2 categories · 6 tasks» и отдельный янтарный бейдж
**Draft**. Справа: primary «Approve plan», secondary «+ Task», «Share» с
иконкой людей, кебаб «⋯». Пара Draft + Approve plan задаёт жизненный цикл
плана: черновик → утверждённый (и, судя по реализации, — базовый план для
ghost-линий и отклонений).

**Ярус 2 (тулбар).** Слева: синий primary «+ Task» (дублирует шапку — см. §9),
«Today», шевроны ‹ ›, подпись «August 2026». Справа: сегмент-контрол
**Day | Week | Month** (Day активен), кнопка «Filter» с воронкой, дропдаун
«View» с иконкой таблицы.

## 5. Таблица задач

Три фиксированные колонки с заголовками **Task / Owner / Status**, дальше —
канва. Ряды высокие (~56–64px), сетка — тонкие горизонтальные линии.

- **Task** — название; у категорий («Product design», «Development») — шеврон
  сворачивания и полужирное начертание.
- **Owner** — один круглый фото-аватар; у категорий прочерк «—».
- **Status** — чип из четырёх состояний: `Done` (зелёный), `In progress`
  (синий), `Planned` (серый контур), `Blocked` (оранжевый). У категорий вместо
  чипа — **процент готовности** (67%, 50%): свёртка по дочерним задачам.

Под последней категорией — строки-аффордансы «+ Add task» и «+ Add category».
Выбранный ряд (API integration) подсвечен светло-синим по всей ширине,
включая канву.

## 6. Канва Ганта

**Линейка.** Верхняя полоса «AUGUST 2026», под ней ячейки дней 12–26 с днём
недели. Сегодня (13 THU) — синим, с пилюлей **TODAY** под ячейкой и синей
вертикальной линией через всю канву. Выходные (15–16, 22–23) — чуть затемнённые
колонки.

**Бары.** Высота ~24–28px, радиус ~6px:

| Состояние | Отрисовка |
|---|---|
| Done | зелёная заливка `#EAFBF1`, зелёная рамка, **белая галочка в зелёном круге** у левого края |
| In progress | синяя заливка на долю прогресса, остаток — бледно-синий; у «Design prototype» подпись справа от бара: «Design prototype · 60%» |
| Planned | контурный «пустой» бар |
| Blocked | оранжевая пилюля с треугольником-предупреждением и словом «Blocked» прямо на баре |

**Прогноз просрочки.** У «Design prototype» правее бара — пунктирный контур
продолжения и красная вертикальная черта с меткой **«+4d»**: остаток работы
выходит за срок на 4 дня. Это статичная диагностика (бейзлайн/дедлайн против
факта), а не превью перетаскивания — тост о перемещении относится к другой
задаче.

**Зависимости.** Г-образные коннекторы со стрелками, светло-синие:
Design prototype → User testing; Database schema → API integration →
QA & launch. Стрелка выходит из конца предшественника и входит в начало
последователя. Ровно эти связи продублированы в панели («Depends on» /
«Blocks») — граф редактируемый, а не только рисуемый.

**Сводные линии категорий.** Тонкая (~3px) фиолетовая линия от min(start) до
max(end) дочерних задач.

## 7. Инспектор задачи

Заголовок «API integration» + «×». Поля формы:

- **Status** — «• In progress», дропдаун ⇒ статус в этой модели —
  *назначаемое поле*, а не вычисляемое из прогресса и дат.
- **Owner** — аватар + «Alex Morgan», дропдаун ⇒ владелец единственный.
- **Start date / Due date** — «Aug 18, 2026» / «Aug 23, 2026», иконки
  календаря ⇒ обе даты редактируемые.
- **Progress** — «60%» и синий прогресс-бар.
- **Depends on** → чип-ссылка «Database schema»; **Blocks** → «QA & launch»;
  у обоих — иконка связи (управление связями из панели).
- **Description** — абзац текста.
- **Comments** — реплики с фото-аватаром, именем и штампом «Aug 12, 2026
  10:24 AM»; внизу поле «Add a comment…» с кнопкой отправки и аватаром автора.

## 8. Тост

Снизу по центру — тёмная (~`#1F2937`) пилюля с галочкой в круге:
**«Task moved to Aug 19»** и синяя ссылка **Undo**. Канонический паттерн:
перетащил бар → операция применилась сразу → лёгкий путь отмены. Никаких
модалок подтверждения перемещения макет не предполагает.

## 9. Противоречия и условности макета

1. **Панель против канвы и тоста.** Тост говорит «moved to Aug 19», бар
   «API integration» начинается ~19-го, а в панели Start date — «Aug 18».
   Художественная вольность «момента сразу после перетаскивания»; в реализации
   панель обязана обновляться синхронно с баром.
2. **Два «+ Task».** Кнопка есть и в шапке, и primary в тулбаре. В реализации
   достаточно одной; вторая — кандидат на выброс (сейчас у нас одна, в тулбаре).
3. **`67%` у Product design** не сходится с детьми (Done + 60% + 0% ≈ 53%
   равновесно) — либо взвешивание по длительности, либо условные числа. Правило
   свёртки надо выбрать явно.
4. **Семантика «+4d»** двусмысленна: превью drag'а или прогноз просрочки. По
   положению тоста (о другой задаче) и красному цвету — прогноз; наша пара
   «ghost бейзлайна + бейдж отклонения» ей соответствует, но рисуется иначе.
5. **Blocked — статус или следствие?** В макете это чип наравне с Planned,
   при этом QA & launch стоит последним в цепочке зависимостей — блокировка
   могла бы выводиться из незавершённого предшественника. Модель макета
   (статус назначается вручную) проще и, видимо, намеренная.

## 10. Расхождения с текущей реализацией

> **Статус.** Все четырнадцать пунктов закрыты в той же ветке, что и этот
> документ (см. историю ветки `claude/mockup-analysis-1nka8f`): статус стал
> хранимым полем с миграцией и операциями `set_status`/`add_dependency`/
> `remove_dependency`, появились колонки «Владелец» и «Статус», тост с
> отменой, пять разделов навигации с экранами «Главная», «Мои задачи» и
> «Отчёты», меню «Фильтр»/«Вид»/кебаб, аватары и штампы времени в
> комментариях, Inter в сборке и красный danger. Скрытые темой слои (п. 14)
> либо выпилены из DOM (пилюли, точка категории, имя на полоске), либо
> включаются через «Вид» (легенда, сводка, сноска). Таблица ниже оставлена

## 11. Что делать в первую очередь

Если сводить макет и код дальше, порядок по соотношению «заметность/цена»:

1. **Колонки Owner + Status** в таблице (п. 2–3) — самое бросающееся в глаза
   отличие; требует решения по модели статуса (хранимый vs вычисляемый).
2. **Панель задачи**: прогресс-бар, поле статуса, аватары (п. 4–5).
3. **Редактирование зависимостей** из панели (п. 6) — бэкенд уже готов,
   не хватает только фронтовых операций.
4. **Тост с Undo** после перетаскивания (п. 7) — сейчас отмена почти незаметна.
5. **Подключить Inter** и заменить розовый danger на красный (п. 12–13) — час
   работы, а типографика и семантика цвета встают на место.
6. Filter/View/кебаб (п. 8–9) — рисовать только вместе с реальной
   функциональностью, пустые контролы хуже отсутствующих.

Пункт 14 — отдельное решение: скрытые темой легенда и пилюли либо возвращаются
в новом визуальном языке, либо выпиливаются из DOM, но не живут «невидимками».
